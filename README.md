# 서적부 POS (Book Store POS)

사업자 등록 없이 운영하는 서점용 웹 포스기입니다. 일반 포스기를 쓸 수 없는 환경에서
버튼 클릭만으로 **재고 차감·매출 집계**가 자동으로 되고, 여러 사람이 **실시간으로 함께** 사용할 수 있습니다.

👉 https://keonchue.github.io/seojeokbu-pos/

## 기능
- **개업 / 마감** — 하루 영업을 한 구간으로 묶고, 마감해야 다음 개업이 됩니다
- 판매(계좌이체/현금), 실수령액·차액 기록 (실제 금액과 장부 불일치 대응)
- 할인 (원 / % 전환) + 할인 종류(지역할인·직원할인 등) 기록
- 반품 (부분 반품 지원)
- 카테고리(성경/어린이/일반/기타) 분류와 칩 필터
- 재고 관리 (입고/수정/삭제, 입고단가·거래처·안전재고, 결제수단별 판매 집계)
- **구글 시트 자동 기록** — 기존 스프레드시트에 판매·반품·입고를 그대로 덧붙임
- **재고 변동 이력** — 입고·판매·반품·조정·가격변경을 전부 원장에 기록
- 매출 내역 + CSV 내보내기
- **리포트** — 기간별 매출, 일/월별 그래프, 책별 판매 순위, 기간 CSV
- **백업 / 복원** — 전체 데이터를 JSON 파일로 저장하고 되돌리기
- **휴대폰·태블릿 지원** + 홈 화면에 설치되는 앱(PWA), 오프라인에서도 실행
- Firebase 실시간 동기화 + 로그인(가게 공용 계정)

## 기술
- 단일 `index.html` (프레임워크 없음)
- Firebase Authentication + Firestore (실시간, 오프라인 지원)
- 서비스워커(`sw.js`)로 앱 껍데기 캐시 → 인터넷/CDN 장애에도 화면은 뜸

## 데이터 구조 (Firestore)
| 컬렉션 | 내용 |
|---|---|
| `books` | 책 정보와 현재 재고 (`increment()`로 원자적 차감) |
| `transactions` | 판매·반품 기록 (`type:'return'`이 반품) |
| `stockLogs` | 재고·가격 변동 원장 (입고/판매/반품/조정/등록/삭제/가격변경) |
| `meta` | 최초 세팅 플래그, 구글 시트 연동 설정(`meta/sheet`) |

`stockLogs` 기록은 판매 batch와 **분리된 별도 쓰기**입니다.
기록이 실패해도 판매 자체는 절대 막히지 않게 하기 위함입니다.

## 제목이 같고 분류만 다른 책

`성경이 만든 사람 존 워너메이커` 처럼 **일반판과 어린이판이 따로 있는 책**이 있습니다.
앱은 원래 책을 제목만으로 찾았지만, 지금은 **분류(성경/어린이/일반/기타)까지 같이 봅니다.**
그래서 두 판을 서로 다른 책으로 두고 재고·판매를 따로 잡을 수 있습니다.

- 판매 화면·반품 화면에서는 **제목이 겹칠 때만** 분류 배지를 같이 보여줍니다.
  (겹치지 않는 책은 예전 그대로입니다)
- 재고 되돌리기(반품·기록 삭제)도 분류까지 맞는 책에서만 처리합니다.
- 리포트의 책별 순위, 재고 화면의 결제수단별 집계도 판을 나눠서 셉니다.
- 분류가 없는 옛 기록은 예전처럼 제목만으로 찾습니다.

가져오기(`📋 스프레드시트에서 상품 가져오기`)의 짝짓기 규칙은 이렇습니다:

1. **분류 + 제목이 같은 책**이 앱에 있으면 그 책을 갱신합니다.
2. 없더라도 **시트에 그 제목이 한 줄뿐이고 앱에도 한 권뿐이면** 같은 책으로 봅니다.
   (시트에서 분류만 고친 경우인데, 이걸 새 책으로 만들면 책이 갈라지기 때문입니다)
3. 그 외에는 새로 등록합니다. 이때 미리보기가 **"같은 제목의 다른 책으로 N종이 새로 등록됩니다"**
   라고 알려주니, 의도한 것인지 확인하고 반영하세요.

분류까지 **완전히 똑같은 줄**이 시트에 두 번 있으면 그건 진짜 중복이라 경고가 뜹니다.

## 개업 / 마감

하루 영업을 **개업 → 마감** 한 구간으로 묶습니다. 로그인하면 첫 화면에 `🔓 개업하기` 가 뜨고,
마감은 헤더의 `🟢 영업 중` 칩(또는 ⚙ 설정 → 영업)을 눌러서 합니다.

- **마감해야 다시 개업할 수 있습니다.** 영업 중에는 개업 화면이 아예 안 뜹니다.
- **마감하면 헤더 매출이 0으로 돌아갑니다.** 헤더 매출은 "개업한 뒤로 쌓인 금액"이라
  다음 개업 때 자연히 0부터 다시 시작합니다.
- **거래 기록은 지우지 않습니다.** 매출 내역·리포트·구글 시트는 전부 그대로입니다.
  (초기화되는 건 화면의 집계일 뿐입니다)
- 마감 중에는 **판매·반품이 막힙니다.** 매출 조회·리포트·재고 관리는 그대로 됩니다.
- 마감할 때 그날 실적(개업/마감 시각, 결제수단별 금액, 건수)을 저장하고
  ⚙ 설정 → `📒 지난 마감 내역` 에서 볼 수 있습니다.
- 상태는 `meta/session` 한 문서에 있어서, **한 기기에서 마감하면 다른 기기도 즉시 잠깁니다.**
- 영업일자는 **개업한 날** 기준입니다. 자정을 넘겨 장사해도 그 영업의 날짜를 유지합니다.

마감 요약을 `meta/closings` 문서에 모아 두는 건 의도적입니다. 새 컬렉션을 만들면
보안 규칙을 콘솔에 다시 게시해야 하는데, 그 단계를 잊으면 마감이 통째로 실패하기 때문입니다.

## 구글 시트 자동 기록

기존에 쓰던 스프레드시트를 그대로 두고, 앱에서 판매·반품·입고가 생길 때마다
그 시트의 **계좌이체모음 / 현금모음 / 입고모음** 탭 맨 아래에 줄을 덧붙입니다.
택배비 줄은 결제수단 탭에 적은 뒤 **택배비모음** 탭에도 한 번 더 적습니다
(그동안 손으로 두 곳에 적어 온 방식 그대로).

설치는 `apps-script/Code.gs` 파일 맨 위 주석을 따라 하면 됩니다. 요약하면:

1. 스프레드시트 → 확장 프로그램 → Apps Script 에 `apps-script/Code.gs` 붙여넣기
2. `토큰_만들기` 실행 → 나온 토큰 복사
3. `설치_확인` 으로 네 탭의 머리글을 제대로 찾는지 확인
   (탭 이름을 나중에 바꿨다면 `탭이름_확인` 을 돌려 `TABS` 를 고칩니다)
4. 배포 → 웹 앱 (실행: 나 / 액세스: 링크가 있는 모든 사용자)
5. 앱 ⚙ 설정 → 🔗 연동 설정 에 `/exec` 주소와 토큰 입력

앱에서 **매출 기록을 지우면 시트의 그 줄도 같이 지워집니다.** 이걸 위해 미러가 각 탭
맨 끝에 `기록ID` 열을 만들어 숨겨 두고 거래 번호를 적어 둡니다. 예전에 손으로 적은 줄은
이 칸이 비어 있어서 **절대 지워지지 않습니다.**

지켜야 할 것:

- **웹앱 주소와 토큰은 코드에 넣지 않습니다.** 이 저장소는 공개라서 주소가 드러나면
  아무나 시트에 데이터를 밀어넣을 수 있습니다. 두 값은 Firestore `meta/sheet` 에 둡니다.
- 전송은 **결제가 저장된 뒤 따로** 돕니다. 시트가 죽어 있어도 결제는 막히지 않습니다.
- 못 보낸 기록은 브라우저에 쌓였다가 온라인이 되면 자동으로 다시 갑니다.
  (⚙ 설정에서 밀린 건수 확인 · `📤 지금 보내기`)
- 같은 거래를 두 번 보내도 시트 쪽 `_전송기록` 숨김 시트가 걸러내므로 중복으로 적히지 않습니다.
- 열 위치는 하드코딩하지 않고 **머리글 이름으로 찾습니다.** 지금 시트가 A열이 비어 있고
  B열부터 시작하는데, 나중에 열을 옮겨도 그대로 동작합니다.
- 시트에서 값을 고쳐도 **앱에는 반영되지 않습니다.** 거래는 앱 → 시트 한 방향입니다.
  판매·반품·입고는 반드시 앱에서 하세요.

### 재배포를 잊지 않게 하는 장치

`apps-script/Code.gs` 는 **`git push` 로 배포되지 않습니다.** 저장소에 있는 건 사본이고,
실제로 도는 건 구글에 올라간 코드라서 `배포 관리 → 수정 → 새 버전` 을 해야 반영됩니다.
(`index.html` 등 나머지 파일은 push 하나로 끝입니다)

이 단계는 잊기 쉽고, 잊으면 조용히 옛 코드가 돕니다. 그래서 양쪽에 같은 버전을 박아 뒀습니다:

| 위치 | 상수 |
|---|---|
| `apps-script/Code.gs` | `MIRROR_VERSION` |
| `index.html` | `SHEET_MIRROR_VERSION` |

**`Code.gs` 를 고칠 때는 두 값을 같이 올립니다.** 그러면 앱이 ⚙ 설정을 열 때마다 배포된 버전을
물어보고, 다르면 이렇게 알려 줍니다:

> ⚠ **시트 스크립트가 옛 버전입니다.** 배포된 것 `2026-08-08a` · 필요한 것 `2026-08-08b`

`/exec` 주소를 브라우저로 직접 열어도 지금 배포된 버전이 보입니다:

```json
{"ok":true,"service":"서적부 POS 시트 미러","version":"2026-08-08b"}
```

어느 커밋이 재배포가 필요한지는 이렇게 확인합니다 — 목록에 `apps-script/Code.gs` 가 있으면 필요합니다.

```
git log --oneline --name-only -1
```

### 시트 → 앱 (기준정보만)

거래는 한 방향이지만, **단가·안전재고**는 시트에서 앱으로 가져올 수 있습니다.
⚙ 설정 → `📋 스프레드시트에서 상품 가져오기` → **`🔻 시트에서 바로 가져오기`** 를 누르면
`재고관리` 탭을 읽어 옵니다. 무엇을 덮어쓸지는 미리보기를 보고 고릅니다.

`재고관리` 탭의 **현재재고는 기본으로 꺼져 있습니다.** 그 값은 시트가 거래를 집계해 만든
수식이라, 앱에 되돌리면 앱 → 시트 → 앱 으로 도는 순환이 되기 때문입니다.

체크해도 되는 때는 **시트가 앱의 거래를 다 받아 적은 뒤**뿐입니다. 그때는 두 숫자가 같아서
가져와도 아무 일이 없고, 시트에 손으로 적은 입고·판매가 있으면 그것만 앱으로 넘어옵니다.
반대로 **못 보낸 기록이 남아 있으면 시트가 그만큼 뒤처져 있어서, 가져오면 이미 팔린 재고가
되살아납니다.** 이건 눈으로 판단하기 어려워서 **앱이 큐를 보고 직접 체크박스를 잠급니다** —
밀린 것이 있으면 `현재 재고` 가 잠기고 `📤 지금 보내기` 를 먼저 누르라고 알려 줍니다.

## 실행
정적 웹 호스팅(GitHub Pages 등)에 올려서 사용합니다.
로컬 테스트 시에도 `file://` 이 아닌 웹서버로 열어야 합니다.

```
npx http-server -p 5178 -c-1
# → http://localhost:5178
```

## 배포
1. **먼저** `firestore.rules` 를 Firebase 콘솔 → Firestore → 규칙에 붙여넣고 게시
   (git push로는 규칙이 배포되지 않습니다)
2. `main` 브랜치에 push → GitHub Pages 자동 재배포

그게 전부입니다. 서비스워커가 우리 파일을 **항상 네트워크 우선**으로 가져오기 때문에
배포할 때 캐시 버전을 올리는 등의 수동 작업이 필요 없습니다.
(캐시는 인터넷이 안 되거나 3.5초 안에 응답이 없을 때만 쓰는 예비품입니다)

## 앱으로 설치하기
- **아이폰·아이패드**: Safari로 접속 → 공유(⬆) → 홈 화면에 추가
- **안드로이드**: Chrome 메뉴(⋮) → 앱 설치
- **PC**: 주소창 오른쪽 설치(⊕) 아이콘, 또는 앱 안 ⚙ 설정 → 홈 화면에 설치하기

## 설정 파일
- `firebase-config.js` : Firebase 웹 설정 (공개돼도 되는 값)
- `firestore.rules` : 보안 규칙 (가게 계정만 접근 허용) — Firebase 콘솔에 게시
- `manifest.json` / `sw.js` / `icon-*.png` : 앱 설치·오프라인용
- `SETUP-firebase.md` : Firebase 초기 설정 안내
- `apps-script/Code.gs` : 구글 시트 미러용 Apps Script (스프레드시트 쪽에 붙여넣는 코드)

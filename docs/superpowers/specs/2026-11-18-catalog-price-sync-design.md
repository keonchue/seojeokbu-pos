# 카탈로그 웹사이트 공개 + 앱 가격·할인 연동 설계

2026-11-18

## 왜

교회 서적부 카탈로그(손님이 번호를 보고 주문하는 책 목록)는 지금 채림 님이 Claude 에서 만든 artifact 링크라
다른 사람들이 안정적으로 들어올 수 있는 진짜 웹사이트가 아니다. 그리고 가격·할인을 `books.csv` 에서 손으로 따로
고쳐야 해서, POS 앱에서 가격이나 할인을 바꾸면 카탈로그와 어긋난다.

목표는 두 가지다.

1. 카탈로그를 누구나 열 수 있는 웹사이트로 올린다.
2. 앱에서 가격·할인을 바꾸면 카탈로그에도 곧바로 바뀐 값이 보인다.

## 목표 / 하지 않을 것 / 실패로 볼 것

- 목표: 가격(정가)과 책별 할인율(`salePct`)이 앱 → 카탈로그로 자동으로 간다.
- 하지 않을 것: **재고는 연동하지 않는다** (사용자 결정). 품절 표시도 없다. 새 책 추가·사진·상세 내용은
  지금처럼 `books.csv` 와 카탈로그 `index.html` 에서 사람이 관리한다.
- 실패로 볼 것:
  - 재고·매출·원장 등 손님이 보면 안 되는 값이 공개 문서로 새어 나간다.
  - Firestore 가 느리거나 막혀서 카탈로그가 비어 보인다 (그때는 CSV 값으로 보여야 한다).
  - 앱이 같은 내용을 쉼 없이 다시 써서 Firestore 쓰기가 불어난다.
  - 시트로 가는 코드가 흔들린다.

## 지금 상태 (확인한 것)

- 카탈로그 원본: `chaelym/seojeokbu-catalog` (비공개, 2026-11-17 생성, 사용자 계정에 push 권한 있음, Pages 없음).
  로컬에 zip 으로 받은 사본이 `seojeokbu-catalog-main/` 에 있다 (POS 저장소에는 넣지 않는다).
- 카탈로그는 정적 페이지 하나: `index.html` 안의 `DATA`(크기·소개·상세사진) + `books.csv`(이름·가격·할인 등).
  둘은 **카탈로그 번호**로 이어진다. 시작할 때 `fetch("books.csv")` 로 CSV 를 덮어쓰고 그린다.
  할인은 `반값할인`(50% 고정 문구) · `할인도서`('할인가 : ○원') 두 가지.
- POS 앱: Firestore `books` 문서 (`title`, `price`, `stock`, `category`, `salePct` …). 색상 칸은 따로 없고 제목에 들어간다.
  보안 규칙상 가게 계정만 읽고 쓸 수 있다. 할인 값은 `promoPct(b)` / `salePrice(b)` 로 계산한다.
- 앱 책과 카탈로그 책을 짝짓는 값이 아직 없다.

## 접근 방식

| 방식 | 내용 | 장단 |
|---|---|---|
| **A. 공개 가격표 문서 (선택)** | 앱이 Firestore 에 손님용 문서 하나를 써 두고, 카탈로그가 열 때 읽는다 | 즉시 반영, 바깥에 맡길 비밀키 없음, 실패 시 CSV 로 돌아감 |
| B. 주기적으로 CSV 다시 쓰기 | Apps Script / GitHub 자동작업이 앱 데이터를 읽어 CSV 커밋 | 늦게 반영, 앱 데이터 읽기 비밀키를 바깥에 둬야 함 |
| C. 앱의 '카탈로그 반영' 버튼 | 앱이 GitHub API 로 CSV 를 올림 | 공개된 앱 코드에 GitHub 토큰이 들어감, 누르는 걸 잊으면 그대로 |

사용자가 A 를 골랐다.

올릴 곳도 세 가지를 봤다: 사용자 계정 새 공개 저장소 / 채림 님 저장소를 공개 전환 / POS 저장소 안 `catalog/` 폴더.
사용자가 **사용자 계정의 새 공개 저장소**를 골랐다 (채림 님은 함께 고칠 사람으로 초대).

## 설계

### 1. 카탈로그 사이트 올리기

- 새 공개 저장소 `keonchue/seojeokbu-catalog` 를 만들고, `chaelym/seojeokbu-catalog` 의 최신 `main` 내용을
  그대로 옮긴다 (zip 사본이 아니라 원본 저장소에서 받아 최신본을 쓴다).
- GitHub Pages 를 `main` / 루트로 켠다 → `https://keonchue.github.io/seojeokbu-catalog/`.
- 채림 님(`chaelym`)을 협업자로 초대한다 (초대는 바깥으로 나가는 일이라 그 시점에 사용자에게 한 번 더 확인).
- README 의 고치는 법을 새 저장소 기준으로 바꾸고, 가격·할인은 이제 앱에서 바꾼다는 걸 적는다.
- 기존 artifact 링크는 건드리지 않는다. 새 주소로 바꿔 안내하는 건 사용자·채림 님 몫.

### 2. 앱: 카탈로그 번호 연결

- 책 문서에 `catalogNo` (숫자, 없으면 연결 안 됨) 를 둔다.
- 책 수정 화면에 "카탈로그 번호" 칸을 넣는다.
- 설정에 **카탈로그 연결** 화면을 하나 둔다 (처음 117줄을 한 번에 잇기 위한 것):
  카탈로그 사이트의 `books.csv` 를 읽어 줄마다 (번호 · 이름 · 색상) 를 보이고, 이름+색상이 앱 제목과
  가장 비슷한 책을 미리 골라 둔다. 사용자가 확인·수정한 뒤 한 번에 저장한다.
  같은 번호를 두 책에 줄 수 없게 막는다. (내 결정: 번호 하나 ↔ 앱 책 하나)
- 택배비 같은 책(`isShipping`)은 연결 대상에서 뺀다.

### 3. 앱: 공개 가격표 쓰기

- 문서 `public/catalog`:
  ```
  { items: { "1": { price: 45000, salePct: 0 }, "12": { price: 155000, salePct: 50 }, … },
    updatedAt: <serverTimestamp> }
  ```
  `price` 는 정가, `salePct` 는 `promoPct(b)` 값. 재고·제목·원가 등 그 밖의 값은 넣지 않는다.
- 언제 쓰나 (내 결정): 책 목록 스냅샷이 서버에서 온 것이고 보내지 않은 쓰기가 없을 때
  (`!fromCache && !hasPendingWrites`, 지금 `mergeShippingBooks` 와 같은 조건) 연결된 책들로 `items` 를 만든다.
  마지막으로 읽거나 쓴 `public/catalog` 내용과 다를 때만 쓴다. 여러 기기가 같이 써도 내용이 같으니 문제없다.
- 책을 지우거나 연결을 빼면 그 번호가 `items` 에서 빠지고, 카탈로그는 그 번호를 CSV 값으로 보여 준다.

### 4. 보안 규칙

```
match /public/catalog {
  allow read: if true;
  allow write: if isStore();
}
```
나머지는 그대로 잠겨 있다. 규칙은 사용자가 Firebase 콘솔에 올려야 한다 (그 전엔 카탈로그가 CSV 값으로 보인다).

### 5. 카탈로그: 가격표 읽기

- 시작할 때 CSV 와 함께 Firestore REST 로 읽는다 (SDK 없이):
  `GET https://firestore.googleapis.com/v1/projects/seojeokbu-pos/databases/(default)/documents/public/catalog`
- 3초 안에 못 읽거나 오류면 무시하고 CSV 값으로 그린다. 둘 다 끝나면(또는 시간 초과) 한 번 그린다.
- 번호가 `items` 에 있으면 그 번호의 가격·할인은 앱 값이 이긴다:
  - `salePct > 0`: 정가를 긋고 할인가(`round(price × (100 − pct) / 100)`, 앱과 같은 식)와 **"N% 할인"** 배지.
    지금의 '50% 할인' 고정 문구를 이 비율로 바꾼다. CSV `반값할인` 칸은 연결된 번호에서는 무시한다.
  - `할인도서`(CSV) 책은 자리(할인 도서 칸)는 CSV 를 따르고, 보이는 값은 앱의 최종가로 '할인가 : ○원'. (내 결정)
  - `price` 가 0 이면 지금처럼 '가격 문의'.
- `items` 에 없는 번호, 앱에 없는 책은 지금과 똑같이 CSV 값.

## 지켜야 할 것

- POS 쪽 변경은 커밋 전 Codex 리뷰 (CLAUDE.md). 책 수정 저장 경로가 시트로 가는 기록(stockRecord 등)과
  얽혀 있으면 시험용 시트로 계약 시험도 돌린다. `Code.gs` 는 고치지 않는다.
- 카탈로그 쪽은 새 저장소에 따로 커밋한다. `seojeokbu-catalog-main/` 사본은 POS 저장소에 넣지 않는다.

## 만드는 사람에게 남긴 것

- `public/catalog` 를 처음 읽는 방법(onSnapshot 이든 getDoc 이든).
- 카탈로그 쪽 코드 배치.
